# Plan Document: network-resilience

## 1. 개요
* **Feature**: 절대 끊기지 않는 재생 (Zero-Stuttering Priority)
* **Goal**: 호주/해외 네트워크 환경에서 패킷 유실이나 지연이 발생하더라도 오디오 재생이 멈추지 않도록 HLS 버퍼링 전략과 iOS 네이티브 스트림 최적화를 전면 개편합니다.
* **Target Users**: 잦은 버퍼링에 지친 호주 거주 라디오 청취자.

## 2. 요구사항 (Requirements)
* 10초~30초 가량 생방송과 지연이 발생하더라도 **"재생 멈춤"**을 최우선으로 방지할 것.
* 네트워크 일시 단절 시 섣부르게 다음 채널로 넘어가기보다는 넉넉한 버퍼를 재확보한 뒤 안정적으로 재개할 것.
* iOS 네이티브 HLS 플레이어의 자동 버퍼 관리 한계를 보완하기 위한 자바스크립트 기반의 헬스체크 및 리커버리 로직 강화.

## 3. 기술적 해결책 (Technical Approach)
* **[개선 1] HLS.js 버퍼링 극대화 (Non-iOS)**:
  * `liveSyncDurationCount`를 기존 2에서 5로 늘려 라이브 엣지에서 여유 있게 떨어져 재생.
  * `maxBufferLength`를 15초에서 60초 이상으로 대폭 상향.
* **[개선 2] iOS 네이티브 스트림 헬스체크 강화**:
  * 멈춤(`stall`) 감지 시 바로 다음 소스로 넘어가는 임계치(`STALL_SWITCH_SEC`)를 10초에서 15초로 늘려 기다리는 시간 확보.
  * 멈춤 후 라이브 엣지로 점프할 때, 무조건 최신이 아닌 "안전 마진(Safe Margin)"을 둔 과거 시점으로 점프하여 버퍼를 즉시 채우게 함.
* **[개선 3] 재연결 로직 안정화**:
  * 네트워크가 완전히 끊겼다가 돌아왔을 때 부드럽게 기존 세션을 버리고 새 세션을 맺는 `recoverMediaError` 로직 세분화.

## 4. 제약사항 및 위험 요소 (Constraints & Risks)
* 생방송과의 지연(Delay)이 최대 30초에서 1분까지 늘어날 수 있음 (시보 타이밍이 안 맞을 수 있으나 끊김 없는 청취를 위해 감수).
* 과도한 버퍼링은 모바일 데이터 사용량을 일시적으로 늘릴 수 있으나, 오디오 스트림(128kbps)이므로 전체 용량에는 큰 무리 없음.

## 5. 일정 및 작업 분할 (Tasks)
* [ ] Task 1: `index.html` 내 HLS.js 설정값 수정 (버퍼 및 타임아웃 상향).
* [ ] Task 2: iOS 네이티브 오디오 멈춤(Stall) 시 점프 로직 변경 (안전 마진 확보).
* [ ] Task 3: 헬스체크 타이머 최적화 (기다림 vs 전환 비율 조정).

## 6. Executive Summary
### Executive Summary
이 기획은 "지연(Delay)이 생기더라도 절대 멈추지 않는(Zero-Stuttering)" 라디오 청취 경험을 호주/해외 사용자에게 제공하는 것을 목표로 합니다.

| Problem | Solution | Function UX Effect | Core Value |
|---------|----------|-------------------|------------|
| 잦은 버퍼링과 재생 멈춤 | HLS 버퍼 60초 확보 및 라이브 엣지 이격 | 재생 중단 횟수 90% 이상 감소 | 쾌적하고 스트레스 없는 연속 청취 경험 제공 |
